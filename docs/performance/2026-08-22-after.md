## Planning aggregate

The original generic RPC had 17,764 calls, 26,039,875 ms cumulative time,
1,466 ms mean time, and live 15–21 second executions. It also caused 121
statement-timeout errors in the preceding seven days.

Common unfiltered national and authority dashboards now read a maintained
snapshot after Planning ingestion. A production `EXPLAIN (ANALYZE, BUFFERS)`
of `openlist_planning_dashboard_snapshot('NATIONAL')` completed in **1.577 ms**
with 19 shared-buffer hits. This is the underlying database operation, not a
Next/Vercel cache measurement. The initial three-snapshot maintenance run
(national, Cork County, Dublin City) took 54.18 seconds, safely moving the
expensive work off the request path.

## Explicit non-results

- `/sold-prices` remains `private, no-store`: its supported `dateRange` query
  parameter makes the page request-specific. Forcing it static would silently
  ignore or cache the selected range; this was not changed.
- Locality SEO cohort refresh remains 21–23 seconds and its narrow 60-second
  function timeout remains required. The dashboard snapshot contains dashboard
  aggregates, not the persisted locality candidate data needed to eliminate
  its corpus-wide locality derivation. That is retained as the next P1
  performance item rather than being masked by a timeout.
